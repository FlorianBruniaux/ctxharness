AI INSTRUCTION TESTING · NO LLM

Test your AI instructions
against your code.

CTX Harness checks documented facts against your repository and audits Claude Code and Codex configuration. It runs locally as a CLI or TypeScript library.

Catch outdated facts in CLAUDE.md and AGENTS.md before you reuse them in a coding session. Keep the same checks in CI.

THE PROBLEM

Your code changes. Your agent instructions drift.

Your tests can pass while CLAUDE.md still points to yesterday’s architecture. Shared agent configuration can also drift away from the profile a project is meant to use.

DOCUMENTED PATH

A file moved.

The instructions mention src/auth/config.ts, but that file is gone.

fileExistsMismatch

PACKAGE SCRIPT

A command disappeared.

The docs say npm run typecheck, but package.json has no typecheck script.

packageScriptMismatch

PROFILE CONTRACT

An unwanted tool remains.

The backend contract forbids the design MCP, but .mcp.json still declares it.

doctor --expectMismatch

Illustrative cases. CTX Harness reports the supported claim or declaration that fails its check so you can correct the source.

FILES TO EVIDENCE

Choose what to inspect. Get findings you can verify.

The checks run against local files with no LLM, prompt or model API key. You select the host, project or global scope, and any explicit expectations.

WHAT YOU CAN CHECK

Check the instructions, the configuration and the contract.

DOCUMENTATION DRIFT

Verify facts in AI instructions.

Check supported paths, npm scripts, versions, counts and regex captures against local sources. Start with a scan, then keep assertions in .ctxharness.yml.

scan · init · run

CONFIGURATION AUDIT

Inspect Claude Code and Codex.

Diagnose supported instructions, rules, skills, agents, hooks and MCP declarations. Select project configuration, personal configuration or both.

doctor --host both --scope project

EXPLICIT EXPECTATIONS

Check a project profile.

Require or forbid named files and MCP declarations in Claude project configuration. A failed or unresolved explicit requirement blocks the requested contract.

doctor --host claude --scope project --expect backend.expectations.json

Source sizes and coverage

Measure source bytes and expose supported, unsupported or unresolved surfaces. Estimates remain separate from observations.

Portable JSON

Export versioned, validated evidence for other tools, omitting raw paths, arbitrary messages and credentials.

Optional comparisons

Compare configuration snapshots or inspect caller-selected tool availability without running the tools.

Know what a pass means.

            

              Does it use an LLM?
              

                No. CTX Harness runs deterministic checks against supported local facts and
                declarations, without a model API call.
              

            

            

              Does doctor run my hooks, tools or MCP servers?
              

                No. Configuration diagnosis reads declarations and supported local paths. It does
                not execute hooks, start MCP servers or authenticate connections.
              

            

            

              Can a green CI job contain failed diagnostics?
              

                Yes. A workflow can keep a failed diagnostic step advisory with
                continue-on-error. Validating the portable report confirms its format,
                even when its findings include failures. Check the raw step outcome and the active
                merge policy separately from the job’s final color.
              

            

            

              Does every UNKNOWN fail CI?
              

                No. A general configuration audit can exit 0 with warnings or unknowns. An explicit
                expectation selected with --expect fails its contract when it cannot be
                verified.
              

            

            

              Does a clean report prove the agent performs better?
              

                No. Static checks do not prove effective client loading, task quality, token savings
                or latency. Those require separate runtime evidence.

LOCAL CLI · TYPESCRIPT LIBRARY

            
Run a check against your own files.

            Source install instructions ↗
          

          

            
Build the tagged source

            
git clone --branch v0.6.0 \
  https://github.com/FlorianBruniaux/ctxharness.git
cd ctxharness
npm exec --yes --package=pnpm@10.11.0 -- \
  pnpm install --frozen-lockfile --ignore-scripts
npm exec --yes --package=pnpm@10.11.0 -- pnpm build

          

          

            
Try the backend contract.

            

              Download the expectation file into the repository you want to check. Replace
              /path/to/ctxharness in the command with your source checkout’s absolute
              path, then run it from the repository being inspected.
            

            
            

              For documentation drift instead, start with scan CLAUDE.md. For a
              configuration inventory, use doctor --host both --scope project.
            

          

          

            

              Terminal · from your repository
            

            
node /path/to/ctxharness/packages/cli/dist/index.js \
  doctor --host claude --scope project \
  --expect .ctxharness-expectations.json \
  --format json
